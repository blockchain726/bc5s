# BC5s audit, November 25, 2026

The research integration has confirmed reliability bugs. The main order-book
models also have weak recent results; the evidence does not support attributing
their losses to a reversed prediction or settlement label.

Times below use America/Chicago (CST). This review used the existing source,
round and event logs, the paper SQLite ledger, and read-only local status calls.
It did not start the main bot or place orders.

## Confirmed research faults and patches

- `logs/model_lab/training.log` contains six failed scheduled training attempts,
  all ending in Windows sharing violations while replacing the feature cache's
  JSON manifest or NPZ dataset. The two active Market Memory versions still date
  from November 18; the scheduled six-hour fits have not produced a successor.
- `logs/model_lab/supervisor.log` contains 194 lab exit/retry messages. Its recent
  tracebacks show publication of `status.json` failing with the same sharing
  violation. The exception handler called the same reporting function again,
  allowing that second error to terminate the process.
- A training failure set `last_error`, but the next successful price request
  cleared it. The dashboard could therefore stop showing a failed fit while
  continuing to advertise its retraining schedule.

`tools/atomic_files.py` now publishes JSON and NPZ files through private temporary
files and retries replacement after brief sharing locks. A persistent failure
preserves the previous destination and still raises an error. The lab catches
reporting I/O errors in both its regular loop and error path, and retains training
errors separately from transient collection errors until a fit succeeds.

The patch changes cache publication and research error handling. Frozen model
artifacts, prediction features, trading logic and real-money settings were not
changed. The running lab has not been restarted to load these changes, and a
complete new production fit has not been validated.

## Integration and accounting checks

- All 2,984 current-fit winner labels agree with their logged start/end prices.
- All 3,179 calls with a LightGBM probability after the last model selection
  agree with that probability's direction. This checks the logged call mapping;
  it is not an independent reconstruction of every historical inference.
- In the current fit, the interval from feature snapshot to service answer has
  median 0.183 seconds and 95th percentile 0.278 seconds. Six books were available
  in 2,968/2,984 answers; twelve had five and four had four. This does not test
  every live execution step or exclude all timing issues.
- The last 24 hours have three missing service answers and 153 feature snapshots
  marked with bad data quality. Paper scores include observations that would
  not necessarily pass real-order checks.
- An approximately 85-minute round-log gap runs from November 24 at 23:25:56 to
  November 25 at 00:51:25. Logs near it show DNS failures across exchange feeds
  and browser recovery. This establishes a collection interruption; it does not
  identify one definitive cause for the entire gap.
- Order-book dashboard rows normally book the quoted payout, while final pools
  can change and the stake affects the payout. For DeepLOB in fit 6, the quoted
  calculation is +$3.23 versus -$0.93 at final pools. The difference is not
  consistently optimistic across models: LightGBM is -$69.35 quoted versus
  -$68.91 at final pools. Paper P&L should not be read as a wallet balance.

The real-order log since November 17 contains 956 accepted orders, 479 wins
(50.10%), and -$38.80 booked net. The last accepted order settled November 18
at 09:23:42. The saved campaign is at -$40.3183 against its $40 limit; that is an
intentional order restriction, separate from predictive performance.

## Current state and validation

The main bot was stopped at the owner's request at approximately 00:55 on
November 25. Its API on port 8765 refuses connections, and no main bot process
is running. The order-book service remains available on port 8766. Because the
lab and price recorder rely on the main bot for BC prices/results, leaving them
running does not supply new BC observations while it is stopped.

Validation: `214 passed` with the existing SciPy filter-coefficient warning.
New regression cases cover transient and persistent locks, concurrent writers,
a real Windows reader holding a file without delete sharing, continued collection
after reporting failures, and retention/clearing of training errors.

A separate cache preparation against copies of the real cache files completed
with 25,181 rows, 290 feature columns, 10,655 rows with known books, and 4,077 exact
settled live vectors. Its temporary directory was removed. Production cache and
model artifacts were not replaced by that check.
